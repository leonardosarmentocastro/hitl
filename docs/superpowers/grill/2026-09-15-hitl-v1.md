# hitl v1 — grill-me output (2026-09-15)

Input for the brainstorming session that writes `docs/superpowers/specs/<date>-hitl-v1-design.md`.
Everything below was decided one question at a time in a `/grill-me` session held in
treasury-2; treat each decision as fixed unless the brainstorm finds a contradiction, in
which case surface it to the human rather than silently re-deciding.

## The problem

treasury-2 has a working human-in-the-loop workflow: 6 agents, 6 commands, a Stop hook,
`review-context.md`, a delivery-chain doctrine split across `CLAUDE.md` and `AGENTS.md`, a
wipe script + GitHub Action, and tests for the scripts. The user wants to reuse it in other
repositories — the first real target is a contractor client's repository, hosted on
**GitLab**, where peers must be able to review and contribute to the guardrails as pull
requests. The workflow must be packaged without treasury's domain (`CONTEXT.md`) or stack
(stories, accessibility, Mantine, e2e ports, lefthook config, dependency holds).

## Decisions

### D1 — Vehicle: a Claude Code plugin plus an init command (not an npx wizard)

A plugin can carry commands, agents, hooks and skills, but cannot put files into a repo.
So the plugin ships an `/hitl:init` command that scaffolds the repo-side files from
templates under `${CLAUDE_PLUGIN_ROOT}`.

### D2/D3 — Installer-only (shadcn model); the repo owns everything that runs

The plugin ships **no runtime**. Its commands are exactly: `/hitl:init` (with `--adopt`),
`/hitl:customize`, `/hitl:diff`, `/hitl:help`. Everything that runs — agents, commands,
hook, doctrine, scripts — is written into the target repository and owned by it. Workflow
commands keep their plain names (`/review-spec`, not `/hitl:review-spec`), so there is
never a plugin/repo pair of the same command. treasury-2 today is what an installed repo
looks like: "an ejected hitl".

Why: the primary use case is a company repo where guardrail changes go through PR review,
not through a plugin cache refresh. Rejected: a runtime plugin with config-driven knobs
(`review-context.md` generalised) plus an eject escape hatch — eject *is* the install here.

Facts that led here: a plugin lives in `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`
plus an `enabledPlugins` flag (user scope in `~/.claude/settings.json`, or project scope in
the repo's `.claude/settings.json` with `extraKnownMarketplaces`). Plugin commands are
namespaced `/plugin:command`; a project command in a subdirectory of `.claude/commands/` is
still invoked by its bare name.

### D4 — Doctrine lands in one owned file: `HITL.md`, imported from `CLAUDE.md`

`/hitl:init` writes `HITL.md` at the repo root (delivery chain + the portable half of
treasury's `AGENTS.md`: feature branches, stacked PRs, trimmed TDD, specs and plans, review
gates, pull requests, delivery slices) and adds one `@HITL.md` line to `CLAUDE.md` (created
if absent). Stack rules stay in the repo's own `AGENTS.md`. The agents' read list gains
`HITL.md`. `/hitl:diff` compares `HITL.md` to its template cleanly.

### D5 — Core vs optional: a section is core iff a command or agent reads it by name

| Piece | Verdict |
|---|---|
| Delivery chain, specs and plans, review gates, delivery slices, pull requests, feature branches, stacked PRs | Core |
| TDD | Core, trimmed of treasury's coverage paragraph |
| Wipe script + CI wrapper | Core-adjacent: installed, or the doctrine sentence becomes "deleted by hand after merge" |
| Scare-score anchors (`review-context.md`) | Core template; 5–8 get placeholders |
| Stories, accessibility, e2e harness, CI jobs, lefthook, dependency holds, web review specifics | Treasury stack — **never shipped** |

Optionals are **discovery-driven**: init reads the tree (remote host; `.github/workflows`,
`.gitlab-ci.yml`, `.buildkite/`; `e2e/`, `playwright.config.*`, `cypress/`; `.storybook/`;
`lefthook.yml`, `.husky/`, `.pre-commit-config.yaml`; `package.json` scripts; existing
`AGENTS.md`/`CLAUDE.md`) and interviews per finding — "I found Playwright under `e2e/`;
adopt the e2e rule?". Accepted optionals contribute **principle text only** to a
`## Testing and gates` section of `HITL.md`:

- e2e: user-visible bugs ship a reproduces-then-proves-fixed e2e written red first; a
  feature's critical happy path gets one; it belongs to the slice that first makes the path
  exercisable (never a terminal "e2e slice" — MIS-SLICED); a pure API fix needs none.
- test tiers: `unit > component > e2e`, the plan names the tests before implementation.
- CI: one terminal check; a red run is read, not re-run; a flaky test is a red job.
- commit hooks: never `--no-verify`; formatting is never a review turn.
- effective-date regimes: a new rule applies to a pilot area and to anything a slice
  touches; grandfathered code is never a finding (pilots are asked, not discovered).
- the repo's **local gate commands** (discovered from `package.json` scripts or asked),
  written to `## Local gates` in the repo's `AGENTS.md` (stub created if absent) — the
  implementer and fixer run "the gates the standards mandate".

Nothing implementation-shaped (ports, folders, libraries) ever comes from hitl. Where
discovery finds nothing and the user did not ask, the wizard says "skipped: no e2e harness
found" and moves on. A repo with no test runner gets the TDD rule's "add the minimal
harness in the first TDD task".

### D6 — Provider shim; `gh` backend only in v1; GitLab is its own feature

Two independent axes, discovered separately at init: the **code host** (PR API, called by
the commands at run time on every slice) and the **CI system** (the wipe job's only
dependency). Selection happens **once at init**, written into the repo; no run-time host
sniffing. Changing host is re-running init.

The mechanism needs five verbs across 8 call sites (`/implement-stack`, `/umbrella-pr`,
`handover` agent):

| Verb | Used for | Fields read |
|---|---|---|
| `create` | slice PR (base = parent), umbrella (draft, base = main) | number; "already exists" |
| `list` | stack table: PRs whose head matches `<feature>-slice-*` or `<feature>` | number, head, base, state, draft, title |
| `view` | umbrella body for in-place replace; reviews + comments in fix-up mode | body, reviews, comments |
| `edit` | replace the umbrella body | — |
| `comment` | append Review decisions | — |

`/hitl:init` writes `scripts/hitl/pr.sh` (name open) implementing them with a normalized
JSON contract — `{number, head, base, state: open|merged|closed, draft, title, body}` —
and one backend file per host. Commands and the handover agent call only the shim. Tested
under `scripts/__tests__/` with a fake `gh` on `PATH`. The contract documents what is
best-effort per host: draft semantics (Bitbucket has none), review-vs-comment, `[skip ci]`,
CI push permission to protected `main`. The word stays "PR" everywhere with one line "a
merge request on GitLab".

**GitLab** (`glab mr …`, `.gitlab-ci.yml` wipe job needing a project access token because
`CI_JOB_TOKEN` cannot push) is a separate feature with its own spec and plan, verified by
running a full feature on a real GitLab project — a throwaway before the client's. Other
hosts/CIs (Bitbucket, Buildkite) are further backends later. `glab` is not installed on
the development machine; nothing about it is verified yet.

### D7 — Repo `leonardosarmentocastro/hitl`, self-marketplace, plugin name `hitl`

`.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` (`"source": "./"`, as
superpowers does). Install: `claude plugin marketplace add leonardosarmentocastro/hitl` ·
`claude plugin install hitl@hitl`. No `hitl` collides in the official marketplace. Its own
CI runs the template tests. Direction is **one-way, hitl → repos**; treasury-2 is
**untouched** until v1 is proven elsewhere, then adopted (D8).

### D8 — Manifest `.claude/hitl.json`; three-way `/hitl:diff`; `--adopt`

Init writes `{version, provider, ci, files: {path: sha256-of-template-as-written}}`.
Install metadata only — **no command or agent reads it at run time**; delete it and the
workflow runs identically, only diff/help are lost. `/hitl:diff` has, per file, the template
at the recorded version (from the marketplace clone's git history at
`~/.claude/plugins/marketplaces/hitl/`), the repo's current file, and the latest template,
and reports: unchanged / upstream changed, apply / locally edited / both, 3-way merge with
conflict hunks. Applying bumps the manifest and is opened as a PR ("hitl 0.1.0 → 0.2.0").
`/hitl:init --adopt` stamps an already-ejected repo (treasury-2) without touching files;
the first `/hitl:diff` then lists the drift — which is also the check that the templates
were cut faithfully.

### D9 — `/hitl:help` is the state-aware front door

Reads tree + manifest and says one of: not installed → `/hitl:init`; `.claude/agents` +
`HITL.md` present but no manifest → `/hitl:init --adopt`; manifest behind latest →
`/hitl:diff`; up to date → the chain in five lines, the commands, "to change a rule: edit
`HITL.md`/`.claude/` by PR, or `/hitl:customize`". Also reports missing prerequisites.

### D10 — Prerequisites: superpowers hard, `grill-me` soft

Init refuses without superpowers in `enabledPlugins` (prints the two install lines): the
reviewers, the hook and the handover parse artefacts whose *shape* superpowers'
`brainstorming`/`writing-plans` produce. Pocock's skills are user-scope skills
(`~/.claude/skills/grill-me → ~/.agents/skills/…`, via `npx skills add`), not a plugin;
help and README mention `/grill-me` as the recommended start for features whose shape is
unclear. Nothing is vendored.

### D11 — `/hitl:customize`: knob interview plus load-bearing invariants

Grill-style, one knob at a time, the recommendation being the treasury default *with its
reason*. Knobs (final list is the spec's): review rounds (≤2), finding types and
severities, reporting cap (every blocker / ≤5 majors / minors one line), the ~20-file
tripwire, the "no small lane" stance, effective-date pilots, local gates, PR-body sections,
scare anchors. Each knob maps to a location in `HITL.md` or an agent file.

**Load-bearing invariants**, listed in the templates and refused by customize (parsed by
the hook or the commands; change only together with their parser, by PR): the
`**Reviewed:**` line, the `**Owns:**` line, the `Plan:` line, spec/plan filename patterns,
stack-table columns, the six finding-type names, the `docs/superpowers/` path.

### D12 — Init on a populated repo: refuse on collision; idempotent markers

Owned files (agents, commands, hook, shim, wipe script, `HITL.md`): if any exists, stop
before writing anything, list them, offer `--adopt` or removal. Appended files
(`CLAUDE.md`, `AGENTS.md`, `README.md`, `.gitignore`): a `<!-- hitl:start -->…<!-- hitl:end -->`
block (or the `@HITL.md` line) a re-run recognises. `.claude/settings.json` is merged as
JSON — other hooks kept, the Stop hook entry added if absent, and said so. Manifest already
present → "initialised at X; run `/hitl:diff`". Nothing is ever overwritten.

### D13 — README section

Init writes a ~15-line "How changes land here" section for humans: the chain in one
sentence, where specs live and that they are wiped on merge, that `.claude/` and `HITL.md`
are reviewed like code, the hitl version, `/hitl:diff`, and the prerequisites.

### D14 — Proof of v1

A throwaway `hitl-proof` GitHub repo (a minimal Node app with one test), `/hitl:init` with
discovery, then one deliberately boring two-slice feature end-to-end: `/grill-me` →
brainstorm → spec → `/review-spec` → plans → `/review-plan` → handover →
`/implement-stack` → draft umbrella PR → merge → wipe fires. Then `/hitl:init --adopt` on
treasury-2 and read the drift.

### D15 — Bootstrap

This repository was created as an ejected copy of treasury-2's `.claude/` (agents,
commands, hook, settings, fixtures), the wipe script + GitHub Action, the script tests,
a hand-cut `HITL.md`, and a minimal vitest harness — one commit, no spec. From that commit
on, hitl builds itself with the chain; its own `.claude/` is the first consumer of its
templates, and `--adopt` is exercised on hitl before treasury-2.
